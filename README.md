# decomposer-agents-and-skills

Два инструмента мышления для Claude Code, построенных на одной концепции декомпозиции с разными
критериями разреза.

| | Что делает |
|---|---|
| **`/advisor`** | Разбирает повседневные вопросы и решения, отталкиваясь от твоих целей. Дотошный, критичный, не соглашается из вежливости. |
| **`/architect`** | Разбирает задачи разработки до молекул **до** начала кода. Ищет самый дешёвый работающий путь, останавливается на воротах и ждёт «да». |

Философская и научная база обоих — в [CANON.md](CANON.md).

> Репозиторий приватный: в `context/GOALS.md` лежат личные цели.

## Установка

```bash
git clone git@github.com:mstoliarov/decomposer-agents-and-skills.git ~/decomposer
bash ~/decomposer/install.sh
```

Ставится симлинками в `~/.claude/skills/` и `~/.claude/agents/` — то есть работает **во всех
проектах**, а не в одном. Обновление:

```bash
cd ~/decomposer && git pull
```

Переустановка после `git pull` не нужна — симлинки указывают на репозиторий.

После установки перезапусти Claude Code.

## `/advisor`

Наставник. Не выполняет запрос, а сначала выясняет, тот ли это запрос.

Цикл: реконструкция настоящей цели → сверка с твоими целями → декомпозиция разрыва между
текущим и желаемым → копание причины, если это проблема → жёсткая критика (допущения,
pre-mortem, альтернативная стоимость, обратимость) → **обязательный синтез**: как части
складываются, признак успеха, одно следующее действие.

Что он делать не будет: выдавать список задач вместо решения, соглашаться из вежливости,
советовать до понимания контекста, разбирать то, что вообще не стоит делать.

**Первый запуск** при пустом `context/GOALS.md` — короткое интервью на 6–8 вопросов, результат
записывается твоими словами. Можно заполнить файл и вручную.

Цели он берёт из `context/GOALS.md`, `context/PRINCIPLES.md`, Todoist и календаря — через
субагента `goal-context`, который только читает.

## `/architect`

Архитектор. Фазы:

0. **Что за задача** — greenfield / надстройка / модификация, критерий готовности, и явный
   список того, чего в этой итерации не делаем.
1. **Разведка** — параллельно `codebase-cartographer` (что уже есть, где швы) и `option-scout`
   (что уже существует в мире). Правило: не писать то, что можно взять.
2. **Декомпозиция до молекул** — разрез по естественным швам, паспорт каждой части, список
   интерфейсов, все неизвестные превращены в допущения или spike'и.
3. **Эффективность** — ранжированные пути со стоимостью владения и честной ценой каждого,
   плюс вариант «80% за 20%».
4. **Порядок сборки** — последовательность, где после каждого шага система работает, а самое
   рискованное допущение проверяется первым.
5. **Ворота** — план показан, ждёт явного «да». До этого ни строчки кода.
6. **Реализация** по порядку сборки, с проверкой на каждом шаге.

Для работы поверх существующих систем есть отдельная ветка метода: поиск швов, слой защиты
границы, постепенная замена, явный список «не трогаем».

## Структура

```
CANON.md                     философская и научная база метода
install.sh                   симлинки в ~/.claude

skills/advisor/              наставник
  SKILL.md                   цикл и запреты
  references/method.md       развёрнутый метод
  references/questions.md    банк критических вопросов

skills/architect/            архитектор
  SKILL.md                   фазы 0–6 с воротами
  references/decomposition.md  критерий разреза, паспорт части
  references/legacy.md       работа поверх существующего
  references/template.md     шаблон документа декомпозиции

agents/                      субагенты (только чтение)
  goal-context.md            сводка целей и загрузки
  option-scout.md            готовые решения вместо своего кода
  codebase-cartographer.md   карта существующей базы и её швы

context/
  GOALS.md                   твои цели
  PRINCIPLES.md              правила принятия решений
```

## Правка под себя

Правь `SKILL.md` — это обычный markdown, изменения подхватываются при следующем запуске.

Самое полезное, что стоит настроить со временем: `context/PRINCIPLES.md`. Раздел «известные
слабые места» превращает наставника из вежливого в точного — записанная слабость это прямое
разрешение указывать на неё без смягчения.
